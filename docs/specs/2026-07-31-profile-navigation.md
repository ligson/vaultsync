# “我的”导航与账户设置设计

## 目标

登录后的客户端采用两项一级导航：

- “同步”：保留现有同步目录、扫描、上传、拉取和同步状态工作流。
- “我的”：集中处理账户身份、空间使用、服务器连接、应用更新、关于和退出登录。

应用壳使用 `IndexedStack` 保存同步页状态。首次打开客户端只创建同步页，用户进入“我的”后才请求个人资料，避免启动时增加无关网络请求。

## 账户资料

后端 `users` 表以非破坏性方式追加 `username`、`nickname` 字段，并创建 `username <> ''` 的唯一索引。历史用户的两个字段为空，客户端显示时回退为邮箱 `@` 前的部分；用户保存资料时写入明确的用户名和昵称。

新增接口：

- `GET /api/v1/auth/me`：读取账号、昵称、用户名、配额和已用空间。
- `PATCH /api/v1/auth/me`：修改用户名和昵称。用户名统一转为小写并校验格式和唯一性。
- `POST /api/v1/auth/change-password`：校验当前密码后修改新密码，新密码至少 8 位。
- `GET /api/v1/releases/{platform}`：读取公开的对应平台版本元数据，供客户端检查更新。

接口继续使用统一 JSON envelope。修改资料、密码不会删除或重建会话，不会影响同步目录、上传任务、同步历史和加密密钥。

## 头像与数据安全

头像属于账号资料，不属于设备资料。头像选择后由客户端使用账号登录时派生的内容密钥加密，再上传到受保护的 `/api/v1/auth/avatar`；服务端仅保存 `VSAV001` 密文、哈希、大小和更新时间，不能直接读取图片明文。其他设备登录同一账号后拉取密文并在本机解密缓存，因此同一账号在不同设备显示同一头像。

客户端仍限制原始图片不超过 5 MB，服务端为加密包编码膨胀预留 8 MB 存储上限。已有仅存于本机的旧头像，在服务端没有头像且当前设备可以解密时自动迁移一次；服务端已有头像优先于本机缓存。网络不可用或解密失败时保留本机缓存作为降级显示，不覆盖服务端头像。退出登录不删除服务端头像，也不清除本机头像缓存；头像不进入同步目录、上传任务、服务器密文对象或空间用量统计。

## 空间与更新

“我的”页展示后端返回的 `used_bytes / quota_bytes`，空间详情只读，不在客户端计算或清理服务端文件。App 更新先请求平台版本元数据，只有新版本号高于当前版本时提供外部下载入口，不自动覆盖安装；下载和安装仍由用户确认并遵循保留数据的升级流程。

## 迁移与回滚

旧 SQLite 启动时通过 `ensureColumn` 追加字段，默认空字符串；已有用户行、文件对象、同步目录和密钥不变。回滚客户端不会触碰新字段，旧版本继续读取原有列；回滚服务端前应先备份 SQLite，若需要撤回功能只停止调用新接口，不删除字段或索引。
