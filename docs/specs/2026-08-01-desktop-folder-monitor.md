# 桌面同步目录监控设计

## 目标

让 macOS、Windows 和 Linux 客户端在应用进程运行期间监控已绑定的同步目录。文件新增、修改、移动或删除后，客户端自动触发现有扫描、上传和远端拉取流程；移动端继续使用现有定时同步和相册备份流程。

## 性能策略

- 使用 Dart `Directory.watch(recursive: true)` 接收文件系统事件，不为每个文件事件单独发起网络请求。
- 同一目录的事件使用防抖窗口合并，默认 1.5 秒内只触发一次同步；同步执行期间到达的事件合并到下一轮。
- 监听只负责触发同步，扫描、上传队列幂等逻辑和远端游标仍复用现有实现，避免引入第二套一致性规则。
- 同步执行期间暂时抑制监听回调，避免远端下载写回本地后被误判为新的本地上传；同步期间用户改动由下一次兜底扫描补齐。
- 保留现有 5 分钟全量扫描作为兜底，处理操作系统丢事件、网络恢复和应用重新打开等场景。
- 忽略 `.drive_sync` 控制目录以及不存在或无权限的目录；监听异常不阻断手动同步和定时兜底。

## 生命周期与兼容性

- 监听器随同步主页创建和销毁，不创建新的本地持久化数据，不清空已有目录绑定、上传任务、同步历史或密钥。
- 桌面窗口关闭后，当前 Flutter 进程会退出，监听也会停止；后台常驻、托盘和开机启动属于后续桌面发行版能力，不在本次改动中隐式改变用户的退出行为。
- Android/iOS 不启用目录监听，避免移动端后台限制和额外电量消耗。

## 回滚

删除监听器接入并恢复原有定时器即可回滚；本次没有数据库、文件格式或服务端存储迁移。
