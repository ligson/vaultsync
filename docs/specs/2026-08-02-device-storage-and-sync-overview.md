# 设备、空间与同步概览改造

## 背景

同步中心中的“同步状态”和“设备与目录”重复展示同步目录；“我的”中的“使用空间”只能查看容量，无法直观看出设备数量，也无法处理旧客户端留下的空设备记录。

线上数据检查确认，当前账号有 3 台带稳定 `client_key` 且各自拥有同步目录的真实设备，另有 6 条旧客户端或调试阶段产生的空设备记录。这些空记录没有 `client_key`、同步目录和有效会话，不是新增的真实设备。

## 客户端设计

### 同步概览

同步状态页只保留一个“同步概览”区域：

- 顶部展示整体状态、待上传、上传失败、待清理和待处理问题数量。
- 保留失败任务和清理任务的重试入口。
- 保留自动同步状态。
- 下方按设备分组展示同步目录，并标识当前设备。
- 每个目录同时展示待上传、失败、问题数量，以及最近的自动/手动扫描和上传状态。

原独立“设备与目录”区域不再重复渲染，信息字段不减少。

### 设备与空间

“我的”中的“使用空间”改为“设备与空间”，打开独立页面：

- 顶部展示设备总数、已用空间和总容量。
- 每台设备展示名称、平台、同步目录数、占用空间，并标识当前设备。
- 展开设备后展示每个同步目录的短 ID、文件数和占用空间。
- 没有同步目录的设备明确显示为空设备。
- 仅非当前且没有同步目录的设备显示“移除设备”。

## 设备移除安全边界

设备移除采用用户确认、服务端最终校验的非破坏性策略：

- 只能移除当前登录用户自己的设备。
- 客户端禁止移除当前设备，并把当前设备 ID 传给服务端复核。
- 有同步目录、上传会话或删除记录引用的设备禁止移除。
- 删除操作只清理该设备记录、关联登录会话和设备同步游标。
- 不删除 `sync_roots`、`file_versions`、`sync_events`、对象文件、下载目录或任何客户端本地数据。
- 不在升级、启动或迁移时自动清理历史设备。

## 重复注册兼容

新客户端继续按非空 `client_key` 精确复用设备。旧客户端未提供 `client_key` 时，后端复用同一用户下最近一条同名同平台的空设备，避免每次登录继续新增记录。

这项兼容不合并已有设备、不移动同步目录，也不修改已有 `client_key`。

## 数据影响、备份与回滚

本次不修改数据库结构和存储路径，不需要数据迁移。发布后只有用户主动确认“移除设备”时才会删除满足安全条件的空设备记录。

部署前继续按现有发布流程备份 SQLite。回滚应用和后端不会影响既有同步数据；已经由用户主动移除的空设备记录如需恢复，可从部署前 SQLite 备份恢复，但这些记录本身不包含同步目录和文件数据。
