# 同步可靠性与可见性设计

## 目标

- Android 锁屏或切到后台后，正在运行的自动同步和上传继续执行。
- 同一设备的同一同步目录，同一时刻最多运行一个扫描任务和一个上传任务；重复操作给出明确提示。
- 自动和手动扫描、上传都记录目录级状态，可在同步状态页按设备和目录查看。
- 设备较多时使用下拉选择过滤首页目录，并明确标识当前设备。
- 使用空间按最新且未删除的远端对象实时统计，并展示用户、设备和同步目录三级用量。
- App 更新根据当前平台查询安装包，正确解析相对下载地址，并显示打开或下载状态。

## 数据兼容与安全

- 客户端仅在 `SharedPreferences` 新增目录任务状态键，不修改或清空目录绑定、上传队列、同步历史、相册记录和加密密钥。
- 后端不修改现有表字段；容量统计直接读取 `file_versions`、`file_tombstones`、`sync_roots` 和 `devices`，只新增查询索引和只读接口。
- 容量按每个对象最新版本统计，并排除已有删除墓碑的对象，避免历史版本重复计费。
- 所有迁移使用 `CREATE INDEX IF NOT EXISTS`，可以直接回滚代码，已有数据不需要反向迁移。

## 后台同步边界

- Android 在登录后的同步主页启动数据同步前台服务，显示常驻通知，并在页面销毁或退出登录时停止。
- 前台服务用于降低 Activity 进入后台后 Flutter 进程被挂起或回收的概率，现有上传队列和断点续传逻辑保持不变。
- 用户从系统设置强制停止 App 后，Android 不允许继续运行；下次打开 App 由现有队列和定时同步恢复。
- iOS 不承诺持续后台执行。iOS 的长期后台上传需要改造为系统 `URLSession` 后台传输，后续单独设计。

## 任务状态与互斥

- 任务唯一键为 `syncRootId + operation`，`operation` 为 `scan` 或 `upload`。
- 状态包括 `running`、`success`、`failed`，并记录来源 `manual` 或 `auto`、开始/结束时间、数量和消息。
- 页面内使用目录级锁避免并发重入；持久化状态用于展示和异常退出后的诊断，不作为上传队列本身。
- 自动同步遇到正在手动处理的目录时跳过该目录，下一轮定时同步继续补偿。

## 回滚

- 客户端可以移除前台服务、目录任务状态读取和新 UI；新增偏好键保留不会影响旧版本。
- 后端可以移除容量明细接口和实时汇总；新增索引无需删除，也不会改变业务数据。
