# VaultSync 登录会话续期设计

## 背景

当前访问令牌和服务端会话固定 24 小时有效。Flutter 客户端只会在访问令牌尚未过期且剩余不足 1 小时时尝试续期，而刷新接口本身又要求有效访问令牌，因此 App 在后台、锁屏或超过 24 小时未打开后无法自动恢复登录。

本次改造目标是在不延长访问令牌暴露窗口、不清理既有登录和同步数据的前提下，让手机端和桌面端都能稳定保持登录，并兼容尚未升级的客户端。

## 会话模型

- Access Token 有效期保持 24 小时，用于调用普通业务接口。
- Refresh Token 有效期为登录时起 30 天，用于访问令牌过期后的自动续期。
- Refresh Token 使用 32 字节强随机数生成，客户端只保存明文，服务端只保存 SHA-256 哈希。
- 每次刷新同时签发新的 Access Token 和 Refresh Token；旧 Refresh Token 在数据库原子更新成功后立即失效，避免重放。
- Refresh Token 的 30 天截止时间固定，不因刷新而延长。超过截止时间后用户需要重新登录。
- 多个请求同时遇到 401 时，客户端只发起一次刷新，其余请求等待同一个结果，避免令牌轮换竞态。

## 接口约定

`POST /api/v1/auth/refresh` 调整为公开路由，但只有以下两种请求能够成功：

1. 新客户端在 JSON 请求体中提交 `refresh_token`，服务端校验其哈希、有效期、撤销状态和用户状态后轮换令牌。
2. 旧客户端不提交 `refresh_token`，但携带仍然有效的 `Authorization: Bearer <access_token>`；服务端沿用旧逻辑签发一组新会话令牌。

无 Refresh Token 且访问令牌已经过期的请求返回 401。刷新接口虽然不经过统一认证中间件，但不会接受未经校验的用户标识。

登录和刷新响应在原字段基础上新增：

```json
{
  "refresh_token": "仅返回给客户端的随机令牌",
  "refresh_expires_at": "2026-09-02T08:00:00Z"
}
```

客户端解析新增字段时允许字段缺失，以兼容升级期间旧后端的响应。

## 数据库迁移

`sessions` 表非破坏性新增以下字段：

- `refresh_token_hash TEXT NOT NULL DEFAULT ''`
- `refresh_expires_at TEXT NOT NULL DEFAULT ''`
- `revoked_at TEXT NOT NULL DEFAULT ''`

并为非空的 `refresh_token_hash` 创建唯一索引。旧记录全部保留，新字段默认为空；用户、设备、同步目录、上传任务、同步历史、密文文件和密钥均不修改。

部署前应照常备份 SQLite。升级后的服务可以直接读取旧记录，旧记录在访问令牌仍有效时可通过兼容刷新接口获得新的 Refresh Token。

## 客户端存储与退出

- Refresh Token 和到期时间写入现有 `SharedPreferences` 登录存储，不改变设备绑定、同步目录、上传队列、相册备份记录或加密密钥。
- 登录、刷新成功后保存新的令牌；旧后端未返回 Refresh Token 时不覆盖本地已有值。
- 用户主动退出登录时，与 Access Token 一起清除 Refresh Token。
- App 启动时，访问令牌已过期但 Refresh Token 仍有效，应先自动刷新再进入主页。

## 回滚说明

代码回滚不需要回退数据库结构，新字段和索引可以保留且不会影响旧版本查询。回滚到旧后端后，新客户端会退回访问令牌 24 小时有效的行为，超过 24 小时可能再次要求登录；已有用户数据和客户端同步状态不受影响。

如果需要撤销某个刷新会话，应写入 `revoked_at`，不得通过清空整张 `sessions` 表处理。
