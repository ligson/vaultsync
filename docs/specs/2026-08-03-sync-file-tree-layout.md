# 同步主页文件树布局优化

## 问题

当前文件树在手机窄屏下把层级缩进、文件图标、完整路径、状态徽标和操作菜单放在同一行。目录越深，文件名可用宽度越小；较长的状态文字还会继续占用尾部空间，最终导致文件名逐字换行，难以浏览和操作。

## 布局规则

- 文件名固定单行显示，超出宽度使用省略号，不允许逐字纵向换行。
- 文件行尾部只保留固定宽度的操作菜单；同步状态移到文件内容区显示。
- 文件树已经表达目录层级，文件副标题不再重复完整相对路径，只显示大小、更新时间和失败原因。
- 目录每级缩进由 20 像素收紧为 12 像素，并限制最多展示 4 级视觉缩进；实际层级和展开关系保持不变。
- 普通“已同步”状态不在每一级目录重复展示，只有待上传、失败、待清理等需要注意的状态才在目录摘要中强调。
- 根目录摘要不重复展示标题区已有的设备信息，数量为 0 的待上传和问题不占用空间。
- 文件树继续分批渲染，每批最多 150 项，避免大量文件同时构建影响滑动性能。

## 交互与兼容

- 点击目录行继续展开或收起目录。
- 点击支持预览的文件行继续打开在线预览。
- 文件和目录的操作菜单、删除确认及权限边界保持不变。
- 桌面端使用同一套布局；更宽窗口会自然获得更多文件名显示空间，不单独复制一套文件树实现。

## 数据安全

本次仅修改 Flutter 展示组件和测试，不修改同步协议、SQLite、服务端对象、客户端目录绑定、上传队列、同步历史、相册备份记录或加密密钥，不触发文件扫描、上传、下载或删除。
