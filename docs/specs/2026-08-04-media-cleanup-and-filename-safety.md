# 相册自动清理与文件名安全

## 目标

相册备份选择“上传后删除本地文件”后，上传完成且服务器对象已确认时自动批量清理本地照片和视频；同时避免文件名编码异常时误删用户仍可能需要恢复的本地文件。

## 行为规则

- 普通同步目录保持原有行为：单个文件上传确认后按目录策略清理。
- 相册资源在一轮上传完成并持久化任务状态后统一批量提交给系统相册 API，避免逐个调用造成多个系统弹窗。
- Android/iOS 需要系统确认时，只在 App 前台提交删除请求；锁屏或后台上传完成的资源保持 `uploaded`，回到前台后自动重试。
- 系统只返回部分成功时，成功资源记为 `deleted_local`，其余资源进入 `cleanup_pending`，不会重试上传，也不会删除服务器备份。
- 升级前已经是 `cleanup_pending` 的历史相册任务不参加自动批量删除；同步状态页提供一次确认后全部提交的批量操作，保留单项忽略能力。
- 历史任务批量操作不再要求逐项勾选，也不限制每次 10 个；系统或权限失败的项目继续显示待处理。
- 相对路径包含 Unicode 替换字符 `U+FFFD`（`�`）时禁止本地自动删除，任务进入 `cleanup_pending` 并提示先重命名后重新扫描。
- 文件列表将含 `�` 的名称显示为“名称编码异常”，详细信息继续保留原始路径供定位；预览、下载和服务器操作仍使用真实对象信息。

## 数据影响与兼容

- 不删除或迁移服务器 `data/`、SQLite、服务器备份对象、同步历史、目录绑定、上传队列或加密密钥。
- 新增批量清理接口只扩展客户端抽象；现有单项清理接口保留用于兼容旧任务和失败重试。
- 既有任务 JSON 字段和状态值保持兼容。新增自动批量仅消费已完成上传的 `uploaded` 相册任务；历史 `cleanup_pending` 状态不会因升级自动转为删除。
- `PhotoManager.editor.deleteWithIds` 接收完整资源 ID 列表。删除结果按返回的成功 ID 分别落盘，允许部分成功后安全重试。

## 恢复与回滚

- 若新版本出现系统删除权限或插件异常，任务会停留在 `cleanup_pending`，服务器备份不受影响；回滚旧版本仍可按原逐项确认流程处理。
- 文件名已经存储为 `�` 的旧服务器对象无法仅靠界面重新解码恢复原始字节。新版本只阻止继续自动删除，不会改写已有对象名。
