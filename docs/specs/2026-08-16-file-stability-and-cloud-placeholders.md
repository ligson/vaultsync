# 文件稳定性与云端占位文件设计

## 目标

- 普通同步目录中的文件只有在停止写入后才允许上传。
- “上传后删除”不能删除仍在下载、复制或生成中的半成品文件。
- 服务器文件可以在系统文件管理器中按原目录结构浏览，并在打开时按需下载。

## 文件稳定性

普通文件第一次被扫描到时进入 `waiting_stable`，不立即上传。只有文件大小和修改时间连续一致、首次稳定观察和最后修改时间都超过 60 秒后，才进入 `pending`。

扫描直接忽略浏览器、下载工具和 BT 客户端常见的临时后缀：`.crdownload`、`.download`、`.part`、`.partial`、`.tmp`、`.aria2`、`.opdownload` 和 `.!qB`。临时文件完成后通常会被原子重命名为正式名称，届时再按普通文件进入稳定性检查。

上传准备继续使用流式加密缓存。密文生成后以及上传完成请求前再次读取源文件大小和修改时间；发生变化时丢弃未完成密文并把任务退回 `waiting_stable`，不增加失败次数。新上传任务同时保存本次明文 SHA-256；服务器确认后的本地清理除校验大小和修改时间外，还会重新计算待删除文件的 SHA-256，内容不一致时保留本地文件并进入待清理状态。没有哈希的历史任务继续使用原大小和修改时间兼容规则。

该方案每次观察只增加文件元数据读取，不在扫描阶段计算内容哈希，不会因为大目录稳定性判断而读取所有文件内容。额外哈希只发生在配置“上传后删除”或“上传后归档”的文件清理前，用安全性换取一次顺序读取；保留本地策略没有这项开销。

## 系统文件管理器占位

真正的“文件名存在、内容不在本地、双击后自动下载”必须使用操作系统云文件接口，不能用普通软链接或空文件模拟。

| 平台 | 系统能力 | 原目录行为 |
| --- | --- | --- |
| Windows | Cloud Files API | 可以把用户选择的原目录注册为同步根，迁移后在原路径显示占位文件 |
| macOS | File Provider | 必须位于系统管理的 `~/Library/CloudStorage/VaultSync`；可迁移原目录，并在旧位置留下 Finder 别名 |
| iOS | File Provider Extension | 显示在“文件”App 的 VaultSync 位置，不能接管任意原目录 |
| Android | DocumentsProvider | 显示在系统文件选择器的 VaultSync 位置，不能把任意目录变成云占位目录 |

云文件状态统一为“仅云端”“下载中”“本地可用”“正在上传”和“失败”。桌面端提供“始终保留在本机”和“释放本地空间”；打开仅云端文件时，客户端下载密文、本机解密到受控缓存，再交给系统应用打开。

## 目录迁移和数据安全

- 现有普通同步目录不会在客户端升级后自动转换或移动。
- 启用系统云盘前先确认该目录没有运行中的扫描、上传、下载或清理任务。
- Windows 转换前备份本地目录映射，并逐个文件确认远端版本；只对已确认备份的文件创建占位状态。
- macOS 创建系统云盘目录后采用复制校验、切换映射、最后由用户确认是否清理旧目录的顺序；旧路径默认保留 Finder 别名。
- 云盘系统目录必须从普通目录扫描器中排除，防止占位文件被当成新文件重复上传。
- 回滚时保留原目录映射、上传队列、远端版本索引、密文和加密密钥；未完成迁移不得删除原文件。

## 实施顺序

1. 文件稳定性保护和任务状态可见性。
2. App 内服务器文件按需下载、缓存和打开。
3. Windows Cloud Files 同步根与占位文件。
4. macOS File Provider、iOS File Provider 和 Android DocumentsProvider。
