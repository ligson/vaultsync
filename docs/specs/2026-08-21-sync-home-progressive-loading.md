# 同步首页渐进加载设计

## 背景

同步首页原先需要串行完成服务器目录查询、每个目录的远端对象查询和元数据解密后才显示主体内容。当后端或网络响应较慢时，用户只能看到空白页面和中央进度圈，也无法判断已有的本地同步状态是否仍然可用。

## 目标

- 首屏优先展示本地已有的目录、任务、问题和操作状态。
- 服务器目录和远端文件分阶段刷新，已经显示的内容不被阻塞。
- 慢响应、部分目录失败和整体请求失败都有明确且稳定的页面状态。
- 不改变现有持久化数据、同步协议或加密边界。

## 加载流程

1. 页面初始化后，从现有 `SyncRootMappingStore`、`UploadTaskStore`、同步问题和操作状态中构建一份仅存于内存的本地快照。
2. 有本地目录时立即显示可操作的目录视图；没有本地内容时显示稳定骨架屏，不再只显示孤立的中央进度圈。
3. 后台请求服务器同步目录。返回后立即校正本地映射并更新目录摘要，不等待远端文件列表。
4. 远端文件按目录分批加载，每批最多并发 3 个目录；每个目录仍使用现有上限查询 500 个对象，并使用现有密钥在客户端解密元数据。
5. 每批完成后增量更新页面，不会覆盖加载期间刚更新的上传任务或其他本地状态。
6. 上传会话进度校准在首屏展示后后台执行，校准完成时只更新本地上传任务摘要。

## 交互状态

- 背景刷新期间在页面顶部显示 2 px 线性进度条，页面主体继续可滚动、展开和操作。
- 整体刷新超过 1200 ms 时显示“服务器响应较慢”提示，并区分当前展示本地快照还是已加载的服务器内容。
- 单个远端目录加载失败时保留其他已加载内容，页面显示“部分服务器文件加载失败”，不转入全屏错误。
- 服务器目录请求失败但本地有目录时，保留本地内容并显示可读错误；本地也无内容时，显示完整错误页及重试、后端设置或返回登录入口。
- 新一轮刷新使用递增代次标识，过期请求不得覆盖最新页面。

## 数据影响与回滚

本次只调整 Flutter 页面的读取时序和内存状态，不新增或修改 SQLite 字段、本地任务 JSON、目录映射、缓存格式、同步协议或服务器对象。本地快照仅用于首屏展示，不持久化远端明文文件列表。

回滚时可恢复原先串行加载时序，不需要数据迁移或恢复备份；已有上传队列、同步历史、目录绑定、密文文件和加密密钥均不受影响。

## 验证要求

- 目录接口持续未返回时，本地目录必须立即可见，1.2 秒后出现慢响应提示。
- 远端文件接口持续未返回时，服务器目录必须已经可见，完成后文件增量出现且顶部进度结束。
- 无本地内容且服务器失败时，不得留在无限进度动画，必须显示可操作错误页。
