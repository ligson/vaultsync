# 微信 V2 dat 图片预览方案

## 背景

macOS 微信 4.x 会把部分聊天图片保存为新版 V2 `.dat` 容器，文件头形如 `07 08 56 32 08 07`。这类文件不是普通图片，也不是旧版单字节 XOR `.dat`，其内容包含 AES-ECB 加密段和尾部 XOR 段。

VaultSync 当前会完整备份原始 `.dat`，因此服务端对象没有丢失。但如果只把原始容器下载回来，系统图片预览和在线预览都无法直接显示图片，用户体验接近“备份了但不可用”。

## 目标

- 保留原始 `.dat` 作为可恢复归档，永不为了预览删除或覆盖原件。
- 在本机具备解码条件时，为 V2 `.dat` 生成可预览图片内容，用于在线预览、缩略图和后续可选的派生副本上传。
- 图片 key 只在用户明确授权后于本机使用，不上传到服务端，不写入同步协议元数据。
- 没有 key 或解码失败时，继续明确提示“文件已备份，但当前无法在线还原”，避免误导为上传丢失。

## 解码链路

V2 `.dat` 解析规则：

- 0-5 字节：容器标识。
- 6-9 字节：AES 加密段明文长度，小端 uint32。
- 10-13 字节：尾部 XOR 段长度，小端 uint32。
- 14 字节之后：文件内容。

客户端解码时：

1. 校验 V2 包头、长度边界和 AES key 长度。
2. 对开头 AES 段使用用户授权获得的 16 字节 image key 执行 AES-ECB 解密。
3. 拼接中间未加密段。
4. 对尾部 XOR 段使用同账号图片上下文中的 XOR key 解码。
5. 校验结果必须是 JPEG、PNG、GIF、WebP 或 BMP 文件头，校验失败则拒绝当图片展示。

## 授权式 key 获取

后续 macOS 端可以增加“本机微信图片解码授权”入口：

- 只在用户点击 V2 `.dat` 预览、或用户手动开启“生成微信图片可预览副本”时触发。
- 弹窗明确说明：VaultSync 将在本机读取正在运行的微信进程内存，用于寻找当前账号的图片解码 key；key 仅用于本机解码，不上传服务端。
- 用户确认后调用独立 macOS helper 读取微信进程内存，并使用本地 V2 `.dat` 样本验证候选 key。
- helper 返回短生命周期 image key 和 XOR key，主 App 仅在当前会话内缓存。
- 用户取消、系统拒绝权限、微信未运行或 key 校验失败时，回退到原始 `.dat` 已备份提示。

该 helper 不应默认随扫描静默执行，不应扫描聊天数据库内容，不应把 key 写入日志、Crash 上报、服务端接口或明文偏好文件。

## 派生副本策略

拿到 key 后可新增可选任务：

- 对当前设备仍存在的 V2 `.dat` 生成同路径旁路派生对象，例如 `Img/<hash>.jpg` 或 `Img/.vaultsync-preview/<hash>.jpg`。
- 派生对象的元数据标注 `derived_from_relative_path`、`derived_from_hash` 和 `derived_kind=wechat_dat_preview`。
- 原始 `.dat` 继续保留，旧对象不删除、不覆盖。
- 用户关闭该能力时停止生成新派生副本，已上传副本不自动删除。

## 数据影响

本方案只新增客户端解码能力和可选派生副本，不修改 SQLite 表结构、服务端对象布局、同步目录绑定、上传队列、同步历史、VaultSync 加密密钥或既有微信原文件。任何批量转换必须先做只读扫描和用户确认。
