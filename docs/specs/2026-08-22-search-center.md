# 搜索中心设计

## 目标

同步首页负责浏览当前目录，跨同步目录找文件由独立的“搜索中心”负责。这样目录浏览工具栏保持紧凑，也避免用户进入同步目录时误以为搜索会重新扫描或重新拉取远端文件。

## 索引边界

- 索引由 Flutter 客户端从同步首页已有的 `_SyncHomeData.rootViews/fileEntries` 生成。
- 搜索中心打开时只做内存中的元数据映射，不调用同步根目录列表、远端对象列表或元数据解密接口。
- 服务器继续只保存密文和加密元数据，不新增服务器明文搜索接口。
- 文件名、相对路径和筛选条件不会上传服务器。
- 远端文件仍在后台加载时，搜索中心明确提示当前结果只来自已加载、已解密的文件元数据。
- 第一版不新增持久化索引，避免引入新的本地数据迁移和索引一致性问题；后续可增加按同步根增量更新的可丢弃本地索引。

## 功能

- 按文件名或相对路径搜索。
- 按同步目录、设备、文件类型和同步状态筛选。
- 搜索结果显示文件名、路径、同步目录、设备、大小、更新时间和状态。
- 根据已有权限提供在线预览、下载到本地、文件详情和定位到原同步目录。
- 定位只改变同步首页已加载文件树的当前目录，并展开目标同步目录，不触发新的远端请求。

## 性能与数据影响

- 搜索过滤和排序只作用于内存中的索引条目。
- 打开、关闭和使用搜索中心不刷新同步首页，不重建远端文件列表，不重新解密全部远端对象。
- 本次不修改服务器数据、SQLite、客户端同步目录映射、上传队列、同步历史、相册备份记录或加密密钥。
- 回滚客户端时不需要清理数据；未来持久化索引也必须设计为可重建缓存，不能成为用户文件或同步状态的唯一来源。
