# 账号头像服务端同步

## 决策

头像是账号级资料。客户端选图后使用现有登录密码派生的 content key 加密，服务端保存不可读的密文包；同一账号在不同设备登录后下载并解密显示。

## 接口

- `GET /api/v1/auth/avatar`：返回当前用户头像密文，没有头像返回 `404`。
- `PUT /api/v1/auth/avatar`：请求体为 `application/octet-stream` 头像密文，服务端按用户覆盖保存，返回统一 JSON envelope 中的头像元数据。

服务端头像文件放在 `data/avatars/<user-id>/avatar.bin`，元数据放在新增的 `user_avatars` 表。头像不计入同步对象、上传任务、服务器文件对象或空间统计，也不提供公开 URL。

## 兼容与数据影响

- 数据库启动时非破坏性创建 `user_avatars` 表；已有用户、同步目录、SQLite 文件对象、上传队列、同步历史和加密密钥不变。
- 已有本机头像在服务端没有头像时自动加密迁移一次；服务端已有头像优先，不会被本机旧缓存覆盖。
- 服务端保存头像密文和 SHA-256，不保存明文；客户端原图限制 5 MB，服务端密文包限制 8 MB。
- 网络或解密失败时客户端继续显示本机缓存，用户可稍后重试上传；不会删除本机头像或服务端头像。

## 回滚

旧客户端会忽略 `user_avatars` 表和头像接口，不影响原有功能。若回滚客户端，服务端头像密文保留；若回滚服务端，需先备份数据库和 `data/avatars/`，停止调用头像接口即可，不删除同步数据。
