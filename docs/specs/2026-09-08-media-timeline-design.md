# 媒体时间轴设计

## 目标与范围

媒体时间轴用于浏览当前账号下所有设备已备份的图片和视频。页面按年月倒序展示，支持图片/视频筛选、设备筛选、每月游标分页、右侧年月定位、查看原文件和下载原文件。

该页面使用独立媒体索引，不依赖同步首页遍历每个同步目录，也不在打开、返回或切换筛选时拉取并解密全部远端对象。

## 数据链路

新相册媒体的写入链路：

1. 客户端把原图或视频按同步目录配置上传；开启加密时沿用现有 XChaCha20-Poly1305 内容密文格式。
2. 创建上传会话时额外提交可选 `media_index`，包括 `media_type`、`captured_at`、宽高和视频时长。
3. 服务端在完成上传的同一数据库事务中写入 `file_versions`、`sync_events` 和 `media_assets`。
4. 客户端从系统相册生成最大 480px 的图片缩略图或视频首帧，使用账号内容密钥加密后上传。缩略图失败不改变原文件上传成功状态。

浏览链路：

1. `GET /api/v1/media/months` 返回当前账号的月份数量和有媒体的设备。
2. `GET /api/v1/media/items` 只返回选定月份的一页，默认 60 项，使用 `(captured_at, id)` 不透明游标。
3. 客户端只在可见卡片需要时下载、解密小缩略图；不以下载原图生成缩略图作为正常路径。
4. 客户端在本地解密这一页的文件名和路径，服务端始终看不到文件名明文。
5. 点击卡片才下载并解密原图或视频；卡片上的下载按钮复用现有原文件保存链路。

## 服务端索引

`media_assets` 是 `file_versions` 上的附加索引，保存：

- `user_id`、`device_id`、`sync_root_id`、`object_id`、`version_id`。
- `media_type`、UTC `captured_at`、年月数值、宽高、视频时长。
- 加密缩略图的服务端路径、密文字节数和更新时间。

服务端不会从加密 `metadata_json` 猜测媒体类型或日期，也不保存缩略图明文、文件名明文、路径明文或原媒体明文。所有月份、条目和缩略图接口都从认证上下文取得 `user_id`，客户端参数不能越过账号隔离。

远端对象产生 tombstone 后，月份和条目查询立即排除对应索引。原 `file_versions` 和存储对象仍按既有同步删除策略处理，媒体索引查询不会额外删除原文件。

## 历史数据兼容

旧客户端不传 `media_index` 时仍按普通上传处理，协议保持兼容。升级不会扫描服务端密文或猜测历史元数据。

客户端首次打开媒体页后，会通过服务端候选接口获取当前账号所有设备的历史对象，并把本机仍保留的已完成相册任务作为兼容路径，通过 `POST /api/v1/media/indexes` 分批回填：

- `GET /api/v1/media/candidates` 只返回 `media-backup:v1:` 同步根下每个对象的最新活动版本，且排除已有 `media_assets` 索引和已删除对象；分页游标使用服务端 `file_versions.rowid`。
- 候选只包含对象 ID、版本 ID、同步根、加密文件名、加密元数据、密文哈希和大小，不包含文件明文。客户端持账号密钥解密后，依据相对路径/文件名扩展名判断图片或视频，依据路径年月和版本时间生成索引。
- 首批候选找到可识别媒体后立即提交，页面刷新月份摘要；余下候选在后台继续，网络中断后下一次打开从仍未索引的候选继续。

- 服务端验证同步根、对象和版本都属于当前账号，并且同步根是 `media-backup:v1:` 类型。
- 批量写入使用 `ON CONFLICT DO NOTHING`，重复回填返回新增数 0，不修改已有索引。
- 回填只增加索引，不重新上传、不覆盖、不删除 `file_versions` 或原始对象。
- 历史缩略图不在首次打开时批量生成；可见项在本机仍有相册资源时按需生成、加密并上传。
- 某设备已清理掉本地相册资源时，该设备的历史媒体仍可查看和下载原文件，但在对应加密缩略图补齐前显示占位图。

即使当前设备没有其他手机的本地任务记录，只要账号密钥仍可用，客户端也能通过候选接口解密并索引其他设备的历史对象。无法解密或没有受支持扩展名的对象会被跳过，不影响原始对象；后续若增加手工回填工具，也必须由持有密钥的客户端显式执行。

## API

```text
GET  /api/v1/media/months?type=&device_id=
GET  /api/v1/media/items?year=2026&month=9&type=&device_id=&cursor=&limit=60
GET  /api/v1/media/candidates?cursor=0&limit=200
POST /api/v1/media/indexes
PUT  /api/v1/media/{mediaID}/thumbnail
GET  /api/v1/media/{mediaID}/thumbnail
```

JSON 接口继续使用项目统一 envelope。缩略图 PUT/GET 使用 `application/octet-stream`，内容是客户端生成的 `VSTH001` 密文；AAD 绑定 `mediaID` 和 `versionID`，避免密文被替换到其他媒体项。

## 页面加载模型

- 页面打开后先请求月份摘要，再请求首月 60 项。
- 首月和后续分页使用 `(user_id, captured_year, captured_month, captured_at DESC, id DESC)` 复合索引，避免为整月媒体额外排序。
- 每个月同一时间只允许一个分页请求，失败保留已加载项并提供行内重试。
- 图片、视频和设备筛选改变后重新请求摘要及首月，不使用同步首页当前设备筛选结果。
- 右侧时间轴选择尚未加载的月份时，只请求该月份首批数据。
- 元数据解密器和账号密钥在页面服务实例中复用，一页条目并行解密，不重复读取 60 次本地密钥。
- 返回同步首页不调用 `_reloadSyncRoots()`，首页继续复用原状态。

## 数据影响、升级与回滚

迁移是非破坏性的：

- 新建 `media_assets` 表和查询索引。
- 给 `upload_sessions` 增加 `media_index_json TEXT NOT NULL DEFAULT ''`。
- 不修改已有上传会话内容、`file_versions`、tombstone、同步游标、目录映射、上传队列、同步历史或加密密钥。
- 不扫描、不移动、不重写服务端已有原始对象。
- 新增 `data/media-thumbnails/<userID>/` 存放可再生的加密缩略图，但升级过程不批量清理该目录。

升级前应使用 SQLite backup API 备份数据库，并保留现有 `data/`。若需要回滚应用版本，旧后端会忽略新增表和列；保留它们不会影响旧上传及下载流程。必要时可以停止新媒体接口和客户端读取，而无需删除表。

未经用户明确确认，不应删除 `media_assets` 或 `media-thumbnails`。即使未来清理这些可再生数据，也必须与 `file_versions`、原始对象、下载目录和客户端密钥严格隔离；删除媒体索引绝不能级联删除原文件。
